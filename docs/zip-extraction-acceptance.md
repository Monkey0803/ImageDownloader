# ZIP 解压：模拟器验收记录

2026-10-26，HarmonyOS 模拟器 `Pura 90 Pro`（`127.0.0.1:5555`）。主包、ohosTest 包均构建并覆盖安装；没有清除原应用数据。

## 构建与自动测试

- OpenSSL 3.5.2 从校验过 SHA-256 的源码包重新构建，libzip 1.12.1 与原生解压模块成功编入 ARM64 主包。
- 主包与测试包的 `assembleHap` 均成功；模拟器运行 `OpenHarmonyTestRunner`：148 通过、0 失败、0 错误。
- ZIP 服务测试覆盖普通 ZIP、传统密码 ZIP、WinZip AES、错误密码、损坏包、路径越界、符号链接、条目数和解压量限制，以及目录层级和同名目标文件夹编号。普通 ZIP 样本同时含图片和文本文件。

## 模拟器实际界面操作

| 操作 | 结果 |
| --- | --- |
| 从系统文件选择器导入普通 ZIP、传统密码 ZIP、AES ZIP | 均出现在“图库 → 压缩包”；原包复制到应用目录并保留。再次导入同名普通包得到 `CodexZipQA-plain (2).zip`。 |
| 普通 ZIP 解压到图库 | 新增 1 张图片，提示跳过 1 个文本文件；图片 SHA-256 为 `d2740fe59aa5aee700048efaf7c53499c10debca21b821c7c30195761ce255af`，与包内原图相同。 |
| AES 与传统密码 ZIP 解压到图库 | 输入本次密码 `pass-1234` 后各新增 1 张图片；文件内容与原图校验值相同。密码不写入下载状态文件。 |
| 应用已有 `Large batch acceptance.zip` 解压到图库 | 新增 2 张 `small.jpg` 图片；内容校验值与原包成员相同，原 ZIP 保留。 |
| 错误密码 | 密码弹窗保留并清空输入；图库记录没有增加，临时解压目录无残留。 |
| 损坏 ZIP 导入 | 导入被拒绝；压缩包和图库记录数量不变。 |
| 重启应用 | 4 个新导入 ZIP 记录和 5 张解压图片记录仍存在。 |

**系统目录目标尚未完成界面验收。** 应用确实打开了系统目录选择器，但本模拟器中进入“我的手机 → Download”后只显示文件夹，未出现可提交当前目录的控件；点击和长按目录均不能选定。因而不能声称系统公共目录写入已由实际界面验证。模拟器上的解压服务测试调用同一 `extractIntoFolder` 路径，以应用可写目录为目标，已验证普通文件、子目录、内容及重复包名自动编号；该测试不能代替系统目录授权与写入的界面验证。

## 文件与记录核对、收尾

- 原生模块先验证并写入本次临时目录；失败后清理临时结果。测试后 `archive-extract` 为空。
- 用应用自身的批量删除功能仅删除本轮 4 个 `CodexZipQA` 压缩包与 5 张解压图片；公共 Download 中 5 个注入样本亦已删除。清理后的状态文件与“重启后状态减去这 9 条本轮记录”的预期对象完全相同：22 条原下载、3 个原压缩包均保留；原压缩包及图片文件仍在。
