# 图库搜索、相似图、收藏标签与轻量编辑

日期：2026-10-26。状态：用户已于2026-10-26确认“认可设计，继续详细计划”；尚未修改产品代码。

## 目标与完成条件

完整实现以下五项，按同一个图库增强项目分阶段交付，不把其中某项改成后续建议：

1. 用户手动建立本地OCR文字索引，按截图、文档图片里的文字检索并打开对应图片。
2. 在现有完全重复文件检查之外，找出缩放、重新压缩后的视觉相似图片，允许查看和对比。
3. 图片可收藏、添加和移除标签，能以此筛选；退出、重启、改名后仍保留。
4. 应用内完成裁剪、90°旋转、画笔和矩形标注，默认生成独立副本并立即进入图库。
5. 在已连接的HarmonyOS模拟器完成真实操作、原生识别、输出像素及持久化验收，恢复原测试前数据。

既有交互继续成立：点击缩略图预览，选择按钮独立；预览默认显示控件、点图隐藏；预览范围沿用当前筛选结果；已下载原图优先。现有未提交改动保留，不执行Git提交。

## 已核实的现状

- 图库只有文件名、来源、格式与排序检索；`LibraryViewModel` / `LibraryQuery`承载筛选。
- `ImageTools.text()`已经封装本地CoreVision OCR并串行管理引擎，但结果只在单图工具面板显示，不持久化；当前整图降采样不适合极长截图的细小文字。
- `DuplicateFinder`已有来源URL、来源文件名、相同文件大小候选的SHA-256内容检查；没有视觉特征匹配。
- 收藏目前用于网页浏览记录，图库图片没有自己的收藏和标签。
- 图片预览、工具面板和双图对比可复用；没有独立编辑页。
- `StoreState`显式序列化下载记录；进度会高频保存整个主状态，OCR长文本不适合放进该文件。
- `LocalPreview.find()`按原始URL优先挑选本地完成项。编辑副本若沿用原图URL，会错误替代之后的原图预览，必须区分身份。
- 模拟器已在线，API26，运行系统OCR和VisionBase能力参数为true。尚未调用识别，不能把能力声明当识别成功。只读基线为21下载、3ZIP、13历史、1网页收藏；开始实际操作前重新采集基线。

## 方案选择

推荐：独立本地图库目录服务 + 原生图像能力 + 应用内轻量编辑页。

| 方案 | 优点 | 代价与取舍 |
| --- | --- | --- |
| 推荐方案 | 索引不跟下载进度反复写盘；标签与浏览共用身份；编辑结果可验证、可控 | 新增目录服务、分析任务和编辑页，需要完整生命周期与迁移测试 |
| 全部并入下载状态 | 状态文件数量较少 | OCR文本和特征随每次下载进度重写，主模型膨胀，影响已有恢复路径 |
| 外部编辑器/在线分析 | 可借用外部功能 | 界面、返回副本和系统组件可用性依赖设备；在线分析额外引入上传和服务依赖，不适合本轮本地功能 |

本轮使用系统OCR和ImageKit，不引入在线识别、云端相似搜索或大型第三方编辑框架。外部系统提供的PhotoEditorExtension接口不等于可直接嵌入的现成编辑界面。

## 用户流程

### 1. 查找与OCR索引

- 图库搜索框支持“全部 / 文件名 / 图片文字 / 标签”范围；默认全部，沿用现有来源、格式、排序筛选。
- 输入只查询已有索引，不自动启动OCR。收藏、标签、来源、格式筛选与关键词共同生效。
- “识别图片文字”允许处理所选图片、当前结果或整个图库，默认当前结果；执行前明确范围和数量。
- 显示已处理数量、成功/无文字/失败数量、当前状态，可取消；已成功保存的条目保留，继续时只处理未完成或已变更文件。
- 搜索结果显示文字命中片段。点击结果仍打开本次结果范围内的图片，保持已有预览/选择分离。
- 面板显示索引覆盖情况，未识别、无文字和失败分别表示，避免把“尚未识别”当作“没有匹配”。支持重试失败、重建当前范围、清空文字索引。
- 单图工具中的文字识别可复用并保存到同一索引；仅对已保存到图库的有效本地资产建立永久索引。
- 静图处理完整图片；长图按原图区域顺序分块识别，使用少量重叠和位置去重，避免把整张长图缩成细条。动图明确识别首帧，实况照片明确识别静态封面。

### 2. 相似图片

- 在现有重复检查区域增加“检查相似图片”；手动分析所选/当前结果/全图库，显示进度和取消。
- 从小尺寸像素生成64位低频感知特征，辅以梯度、平均颜色、透明度及宽高比约束；能识别相同图像的尺寸与压缩变化，不把字节哈希当视觉相似判断。
- 初始匹配门槛：64位低频特征距离不超过8、梯度特征距离不超过10、宽高比相对差不超过5%，并限制平均颜色和透明度差。用独立正负样本校准并固定算法版本，不仅针对一张测试图调参。
- 使用稳定的代表图分组，避免A近似B、B近似C就无条件把A和C归为同一组。
- 每组展示代表图、成员缩略图、文件名和尺寸；“查看本组”进入该组预览，复用现有双图对比。
- 结果称为视觉相似候选，不表示文件内容一定相同。原来的内容一致检查继续独立存在。用户自己选择是否删除，没有自动删图。
- 纯色、透明、线稿、不同内容的相似构图均列入负样本验收。动图和实况照片按首帧/封面比较，并在结果中标明，避免暗示比较了完整动态内容。

### 3. 图片收藏与标签

- 图片工具面板增加收藏开关和标签编辑；图库选择模式支持批量添加/移除标签、设为收藏/取消收藏。
- 网格在文件信息区域显示收藏状态及简短标签，不增加与选择状态重复的角标。
- 图库提供“仅收藏”和标签筛选，能与关键词、来源、格式组合使用；清除筛选可恢复完整结果。
- 标签去除两端空白、去重，保留展示文字。保存错误明确提示，不能只在界面上假装保存成功。
- 收藏和标签按图片ID保存，改名不丢失；删除图片清理其目录元数据。移除标签不删除图片，也不清除OCR索引。
- 未下载的网页图片显示下载后整理入口；永久收藏和标签作用于本地图库资产，避免将网页临时ID误当本地记录ID。

### 4. 轻量编辑

- 已下载图片的工具面板增加“编辑副本”；独立`ImageEditor`页面负责草稿、退出和保存。
- 裁剪支持自由拖动四角、移动裁剪区域以及原比例/1:1/4:3；可恢复全图。旋转每次顺时针90°。
- 标注包括画笔和矩形框，提供红/蓝/黑颜色与笔宽，支持撤销和清空。标注、裁剪与旋转共同使用同一坐标变换，先后操作保持位置正确。
- 预览使用有界底图；保存时按选定裁剪区域的原始像素尺寸解码并应用旋转和标注，不用屏幕截图充当输出，不静默降分辨率。预览和保存都不同时保留多份无界图像缓冲。
- 保存为独立静态副本，容器与画质由设置页「编辑副本科质」决定：不透明源默认 JPEG（质量 90），可选 JPEG 质量 80 或无损 PNG；带透明通道（或透明度未知）的源一律无损 PNG，保留透明像素。动图入口标明“编辑首帧副本”，实况照片为“编辑封面副本”；不把静态结果冒充完整动图或实况照片。
- 文件名带“编辑”后缀并保证不覆盖；图库立即出现新副本并可预览、改名、保存相册、分享、导出和删除。
- 新副本继承标签，默认不收藏；保留来源关系用于详情说明。OCR与相似特征必须针对新像素重建，不复制原索引。副本独立存在，删除原图不会连带删除副本，删除副本也不会影响原图。
- 有改动时退出提示继续编辑或放弃；取消、解码失败、写盘失败不增加图库记录，原文件哈希保持不变。保存失败保留当前草稿以便重试。

## 数据和模块设计

### 目录数据

- 新增`LibraryCatalog`，独立保存收藏/标签元数据以及逐图片的OCR/特征索引。
- 小型收藏/标签目录采用版本化显式DTO和原子替换写入；OCR长文本与特征按图片分片保存，避免单张识别后重写全部长文本。
- 分片以受控图片ID的安全编码/摘要命名，绝不直接用URL或输入文本作路径。
- OCR状态区分未处理、完成有文字、完成无文字、失败；包含版本、文件尺寸/修改时间、必要的内容校验信息。特征索引独立记录算法版本。动图首帧和实况照片封面的源类型、实际读取路径及实际文件版本都参与校验，不能只用实况照片外层包的时间戳。
- 原图改变时使相关OCR和视觉特征失效，收藏与标签保留。已知的改名/移动操作维持同一图片身份，不清空有效索引。
- 删除、清空图库、恢复状态之后按有效ID清理孤立索引；目录读失败隔离损坏条目，不覆盖原图或其他有效元数据。
- 同一图片索引写入与用户修改标签串行合并，避免晚到OCR覆盖新标签；取消/离开页面/切换范围用代次与资产版本校验丢弃过时结果；进入编辑或后台暂停分析，已完成进度可由用户手动继续。

### 编辑副本身份与登记

- 下载记录新增来源类型与原资产ID，旧记录缺省为下载原件，`StoreState`的显式线格式和归一化同步更新。
- 编辑副本使用新ID、新文件、空原始下载URL及独立来源类型；可保留网页来源和原资产关系。不能命中原图URL的本地优先查找。
- 编辑副本进入图库和图库占用统计，不伪装成网络下载任务；任务页的列表和相关清理入口按来源类型处理。桌面卡片仍只统计实际活动任务。
- 导出文件先写专用pending文件，完整关闭并验证后转正；记录持久化成功后才显示“已保存”。失败回滚本次文件和记录。
- 采用本轮编辑操作日志收敛文件与记录的跨写入窗口；启动时只清理本功能可证明未登记的pending产物，不能按模糊路径删除用户文件。

### 主要新增边界

| 层 | 职责 |
| --- | --- |
| model | 图片目录条目、分析状态、索引DTO、编辑草稿与标注几何 |
| util | 文本归一/命中片段、感知特征比较、裁剪/旋转/标注坐标变换与栅格化 |
| service | LibraryCatalog、串行OCR/特征分析、原图区域读取、编辑副本导出与登记 |
| viewmodel | 图库查找/整理状态、分析取消、编辑草稿和保存状态，不持有UIContext或PixelMap |
| view/pages | 图库查找面板、标签编辑、相似组、编辑画布与独立编辑页；Canvas/PixelMap留在专用渲染组件/服务 |
| integration | DownloadStore、StoreState、TasksViewModel、Viewer/PreviewTools、Index装配与main_pages.json路由 |

分析与编辑对图像句柄显式释放；OCR沿用现有单引擎串行约束。感知特征解码与两两比较分批执行，支持取消，不将大PixelMap放入观察模型或持久化文件。

## 界面安排

- 图库顶部保留搜索，增加可收起的“查找与整理”面板，里面放索引、收藏/标签筛选和相似图检查；常用收藏筛选可直接看到。
- 单图收藏、标签与编辑放入现有工具面板，预览底部保持阅读与主要文件操作，避免重新挤满工具栏。
- 编辑页顶部为返回、标题、保存；中间为可操作画布；底部为裁剪/旋转/标注及其当前工具选项。横屏采用紧凑侧栏或分行布局，按钮保持可见与足够触点。
- 标签、文件名、OCR片段和错误提示使用普通用户用语，不显示哈希、DTO、像素格式或缓存路径。

## 实施顺序

1. 目录持久化与旧数据迁移；补齐文件身份、清理和回滚用例。
2. 收藏/标签与组合查询；贯通工具面板、选择模式和重启恢复。
3. OCR索引任务、长图分块、文本查询和状态反馈。
4. 视觉特征、相似分组、候选展示与组内预览。
5. 编辑草稿、预览、原始像素输出、独立副本登记和失败恢复。
6. 主包/测试包构建、逻辑测试、模拟器完整交互、文件内容校验与原数据恢复。

以上是设计内的阶段顺序，完整目标保持五项；正式实现计划在设计审阅后细化到文件、步骤和验证命令。

## 验收矩阵

| 要求 | 必须取得的证据 |
| --- | --- |
| OCR文字检索 | 模拟器真实原生OCR识别中英文夹具中的已知短语，关键词返回正确图片及片段；改名/重启仍命中；无文字、失败、取消、内容改变失效分别验证 |
| 长截图OCR | 上中下含不同已知短语的长图，搜索均能命中；不能只证明整图被识别过或只识别头部 |
| 相似图 | 同图不同尺寸、JPEG重新压缩至少两种正样本；无关照片、线稿/纯色负样本不错误合组；模拟器能打开分组及双图对比 |
| 收藏与标签 | 单图和批量设置、取消与删除标签；组合筛选结果正确；改名及重启不丢失；删除后无孤立可见条目 |
| 裁剪 | 模拟器拖动裁剪框并保存；输出尺寸与已选区域对应，四角颜色/标记证明保存的实际区域；原图哈希不变 |
| 旋转 | 90°/180°/270°、撤销及与裁剪组合；保存宽高和方向正确，EXIF方向夹具预览/输出一致 |
| 标注 | 画笔与矩形在预览、旋转、裁剪后位置一致；输出真实像素含正确红蓝颜色；撤销/清空有效，透明区域不变黑 |
| 副本登记 | 保存后立即出现在图库，重启仍在；文件和原图不同、新ID、来源关系正确；不替代原图URL本地优先预览，不进入网络任务 |
| 失败恢复 | 取消、重复点保存、源文件删除、写盘/状态登记失败、应用中断的pending清理；原图与原记录保持可用 |
| 回归 | 已有选择/预览、过滤范围、静图缩放、长图、GIF控制、浏览控件、文件操作及原状态迁移不回退 |
| 模拟器与清理 | 安装固定哈希包并记录真实截图/层级；重新备份测试前数据；只移除本轮夹具/索引/副本/历史和转发，不重启共享HDC、不操作真机 |

主机用例验证算法、DTO、查询与竞态；系统图像/OCR调用和真实交互必须有模拟器证据。能力参数true、编译通过或用假OCR喂给搜索都不能替代原生识别成功。若模拟器引擎不可用，该成功分支仍未验收，目标保持未完成并如实记录。
