# 批量网页图片下载验收

日期：2026-10-28。主包与 ohosTest 包均构建成功。主要交互验收使用本轮独立创建的 HarmonyOS API 26 手机模拟器，HDC 地址 `127.0.0.1:15555`，避免与已有模拟器的其他界面操作冲突。

## 行为与实现

- 每行支持图片、实况照片包直链和网页；HTML 由“排除”改为网页解析。未知地址先 HEAD，再在浏览器中识别；识别失败可显式作为直链尝试。
- 独立持续挂载 ArkWeb，逐页解析，保留当前浏览页面。导航与采集分别限时 20 秒，采集最多 12 轮；触及边界保留已有图片并提示不完整。
- 每次导航以已提交的空白文档隔开，再接收当前文档的重定向完成事件；关闭、修改输入、离开页面时取消代次并释放网页。旧页面和旧脚本结果不能覆盖新结果。
- 按来源分组，默认全选，支持预览、单张和整组选择、单页重试、打开网页处理。仅最终确认才创建任务；编辑区可直接选择单张或 ZIP，模式在发起解析时快照。
- 微博按目标帖子 ID 校验详情数据，只提取该帖配图；短链最终进入微博也执行此限定。头像、评论、推荐和转发内容不进入结果。
- 单张模式复用原队列；ZIP 每网页一包，直链单独一组。下载、缩略图使用对应来源页与图片域 Cookie；带身份的缩略图请求不跨重定向转发身份。

## 本地夹具与实际文件

夹具：`scripts/serve-batch-pages-fixture.cjs`，仅监听 `127.0.0.1:18767`，通过 HDC rport 反代，不开放局域网端口。

一次输入 `/one.html`、`/two`、`/login.html`、`/a.png`：

- `/one.html`：初始图片、延迟插入和懒加载共 3 张；其中一张必须带该网页 Referer 才能读取。
- `/two`：HEAD 返回 405，GET 为 HTML，仍正常解析出 2 张。
- `/login.html`：明确提示需登录或验证，不影响其余来源。
- `/a.png`：直链组 1 张。合计默认选中 6 张，预览阶段不产生下载任务。

原生交互另验证：选中数量从 6 改为 5 后，滚动至受限来源，打开网页处理、返回结果并仅重试该页，其他来源仍保持选中 5 张。HEAD 返回 405 的无扩展名 `/image` 端点在浏览器中识别为图片，正常形成 1 张直链预览。

单张模式取消第一组的一张图片后，实际入队并完成 5 个任务，均为 1,065 B、400×300 PNG。逐条核对来源页；下载文件均与夹具原始 HTTP 响应字节完全一致，含 Referer 受限图片。

## 重跑与边界

主包、测试包安装并启动本地夹具后，先设置 `DEVICE_TARGET` 为选定的测试设备：

```sh
hdc -t "$DEVICE_TARGET" rport tcp:18767 tcp:18767
hdc -t "$DEVICE_TARGET" shell 'aa test -b com.example.imagedownloader -m entry_test -s unittest OpenHarmonyTestRunner -s timeout 90000 -s batchPagesUi true'
```

- 默认 UI 用例只解析和预览，不入队。新模拟器须先完成系统输入法首次设置；本轮使用不联网的基本模式。
- 加 `-s batchDeselect true` 验证取消第一张；加 `-s batchCommit true` 才实际下载；加 `-s batchZip true` 选择 ZIP。
- `-s batchInput "URL1|URL2" -s batchExpected 4` 可指定本次链接与预期图片数。该预期应按实际内容填写。
- `-s batchHandleFixture true` 用于夹具登录拦截页的打开、返回和重试验证；不自动处理验证码。
- UI 套件由测试代理初始化后加载，避免过早加载 UITest 导致驱动为空；与普通原生逻辑套件隔离。
- 本轮没有执行真实账号登录、人工验证码、视频及微博 Live 配套视频下载；微博 Live 仅提取本轮范围内的静态配图。图片直链实况包沿用原行为。
- 真机未执行本轮验收；构建、宿主逻辑、模拟器交互及文件字节核验分别记录，不互相替代。
- 验收结束停止并删除本轮独立临时模拟器，撤销本轮 rport 并停止夹具服务；下载文件与 ZIP 核验副本保留在本机临时目录，未清除原有设备内容。
- 保留原有工作区改动，未提交或推送。
