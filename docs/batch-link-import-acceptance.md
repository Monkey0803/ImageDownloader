## 输入与逐行结果

输入包含 9 条待处理链接和 1 行无效文本：

首次解析实际显示：

```
可导入 7 条（含待确认 3 条） · 重复 1 · 无效 2
```

逐行状态：图片/签名图片/HEAD-405 图片为“有效 / 图片直链”；重复行显示“重复 / 与第 1 行重复”；`.html` 显示“无效 / 不支持 .html 类型”；无扩展名与未知后缀显示“待确认 / 无扩展名，确认时检测类型”或“扩展名未识别，确认时检测类型”；非链接文本显示“无效 / 不是 HTTP(S) 链接”。

## 按需 HEAD 探测

点击“检查待确认 · 3”后实际显示：

```
可导入 6 条（含待确认 1 条） · 重复 1 · 无效 3
已检查 3 条：确认图片 1，排除网页 1，仍待确认 1
```

- 无扩展名 `image/png` → 有效，原因“已确认图片 · image/png”。
- 无扩展名 `text/html` → 无效并排除，原因“已确认网页，不导入”。
- `application/octet-stream` → 保持待确认，原因“类型未确认（application/octet-stream），仍可导入”。
- HEAD 405 的图片仍按扩展名有效，未因探测失败被排除。

## 证据边界

- 本轮没有实况照片 `.livp` UI 夹具，实况照片仅由 `BatchLinks` 单元测试覆盖“识别为实况照片包并保持有效”；未在模拟器执行做种下载。
- 未连接真机；真机文件与 ZIP 条目核验保留为待验。
- 探测明确不发送浏览器 Cookie；需要登录的链接会显示“需要登录或权限，仍可尝试”，本轮未用受保护链接验证该提示。
- HEAD 与 GET 行为可能不同（如 HEAD 405 但 GET 成功）；本轮覆盖了这一情形，但仍不把 HEAD 结果当作下载能力的绝对保证。
